01 / 先把三种“少”分开

长上下文 Attention 至少有三个可以优化的维度：

  1. 存多宽：一个历史位置保存多少个数？MHA → GQA/MQA → MLA 主要围绕 KV 共享和表示宽度展开。
  2. 存多少条：每个历史 token 都存一条，还是多个 token 合成一条？CSA/HCA 明确压缩序列轴。
  3. 读哪些条：本次 Query 对所有条目做核心 Attention，还是只读一个子集？NSA、DSA、CSA 采用不同的选择机制。

另外还有第四件独立的事：怎么执行。FlashAttention 主要优化精确 Attention 的分块与 IO，PagedAttention 主要优化 KV 的物理分配与管理；它们不能与 MLA/DSA 等表示和可见性机制简单排成互相替代的版本。S7 S8

一句话地图：

方法 核心动作 历史信息在哪里 核心 Attention 看什么
MLA 每个 token 的 KV 联合低秩压缩 每个 token 仍有一条 latent；另有解耦位置分支 通常所有可见历史位置
NSA 摘要 + 原始块选择 + 局部窗口 原始细粒度 K/V 和压缩摘要两种表示 全局摘要、选中块的原始 token、局部 token，三分支
DSA 用轻量 indexer 选 token 按 token 保留 MLA cache，加 indexer key cache Top-k 原始位置对应的 latent
CSA 先按序列合并，再用 indexer 选摘要 历史摘要 + 最近局部 K/V + 压缩状态 Top-k 压缩条目 + 局部原始条目
HCA 更强序列压缩，不做 Top-k 更少的历史摘要 + 最近局部 K/V + 压缩状态 所有可见的强压缩条目 + 局部原始条目

02 / 这不是一条简单的“版本替换链”

2024 · MLA / DeepSeek-V2：解决 KV Cache 太宽的问题。2025 · NSA：独立提出原生可训练、硬件友好的三分支稀疏 Attention。2025 · DSA / DeepSeek-V3.2 路线：在 MLA 底座上增加 token 级学习式筛选。2026 · CSA + HCA / DeepSeek-V4：沿序列轴合并历史，结合稀疏摘要读取与强压缩全读。S1 S2 S3 S4

  • MLA 与 DSA 可以同时存在：表示压缩 + 访问稀疏是两个不同维度。
  • NSA 与 DSA 有共同动机，但选择粒度、索引方式、分支结构和训练路线不同；不能写成“NSA 改名为 DSA”。NSA 论文实验底座为 GQA，不是“给 MLA 固定加三条分支”。
  • CSA 明确使用 DSA 风格的 indexer，但候选从原始 token 位置变成了压缩条目。
  • CSA/HCA 是 V4 中混合部署的两类层，不是“每个 Query 依次经过 CSA 再经过 HCA”。也不是“HCA 淘汰 CSA”。
  • 本次 V4 来源为官方 V4-Flash 快照与 V4 报告；不混入 V4.1 的 CSA2、跨层缓存或其他后续版本机制。

03 / MLA：每个 token 存得更窄，但历史仍然全部存在

Multi-head Latent Attention，多头潜变量注意力。 联合压缩 K/V：历史位置 j 的压缩向量 c_j，经每头的 W_K、W_V 可生成该头的内容 K 和 V。RoPE 使用解耦的位置分支。S1 §2.1

以行向量记法写出内容部分：

K_j = c_j W_K
V_j = c_j W_V
score_j = q (c_j W_K)ᵀ = (q W_Kᵀ)c_jᵀ
output = Σ_j p_j(c_j W_V) = (Σ_j p_j c_j)W_V

第一次吸收：把 K 投影移到当前 Query 一侧。第二次吸收：先对 latent 求和，再做 V 投影。于是推理可以不展开历史 K/V。原始 RoPE 分支、缩放和归一化边界必须保留，不可随意跨过非线性。S1

  • 这是给定 MLA 结构的代数等价重排，不是“任意 MHA 都能无损压成 512 维”。
  • token 轴没有减少：长度 n 的历史通常仍然保留 n 条 latent。
  • 减少 KV 字节数，不等于消除 n² 的全序列 Query-Key 配对。
  • 吸收后内积可能更宽；更少的内存访问不一定对应更少的算术。
  • 本文讲 DeepSeek 的通用 MLA。前面 Kimi K3 例子中的 NoPE、96 heads 和输出 gate 不能直接搬成 DeepSeek 所有版本的常量。

04 / NSA：三条分支各司其职

Native Sparse Attention，原生稀疏注意力。 论文并不是只“选几个块”。它把三个不同来源的 Attention 输出用学习门控合并：S2 §3.2–3.3

  1. Compression 分支：读摘要，掌握全局。 对滑动的原始 K/V 块，用带块内位置信息的可学习 MLP 生成压缩 K/V；Query 对可见摘要做 Attention。这条分支本身就提供输出。
  2. Selection 分支：回到原始块，读细节。 利用 compression Attention 的分数，映射/聚合得到 selection block 的重要性；在 GQA 组内聚合并共享所选块。再读取那些块内的原始细粒度 K/V做 Attention。
  3. Sliding-window 分支：读最近 token。 单独处理局部上下文，防止局部模式压过其他分支的学习。

最后：

o = g_cmp · Attn(Q, K_cmp, V_cmp)
  + g_sel · Attn(Q, K_sel, V_sel)
  + g_win · Attn(Q, K_win, V_win)

门值来自输入经 MLP + sigmoid；并不是三个分支共享一次 softmax，也不保证三个门的和等于 1。S2 式5

为什么要选“块”而不是随意挑 token？

连续块更容易形成合并内存访问并喂给矩阵计算单元。共享 KV 的 Query heads 共享选择结果，可以复用数据加载。论文强调的是算法与硬件共同设计，而不是只追求极低的理论非零数。S2 §3.4

原论文的一个明确配置

项目 论文实验值 不要混淆
压缩块长度 l 32 不是选中块的长度
压缩步长 s 16 有重叠；摘要数约 n/16，不是 n/32
选择块长度 b 64 选中后读块内原始 token
选择块数 k_b 16 包含固定激活的 1 个起始块、2 个局部块
独立窗口 w 512 独立分支，不是从 Top-16 中扣出来

选中细粒度 token 的名义预算是 16×64=1024。还必须另计全部压缩摘要和窗口分支；有重叠，不应把各分支条目数之和当成唯一原始 token 数。S2 §4

**缓存提醒：**未来的 Query 可能要回读较早的原始块；选择少量块不自动意味着可以永久删掉其余原始 K/V。NSA 的稀疏访问不是天然的历史缓存淘汰策略。

05 / DSA：独立的轻量索引器，先挑位置，再做重 Attention

DeepSeek Sparse Attention。 在 DeepSeek-V3.2 中，它基于 MLA 实例化。核心由 lightning indexer + token 级 Top-k + sparse MLA 构成。S3 §2.1

数据流

  • 当前输入生成主 Attention Query，也生成 indexer Query 和各 indexer head 的权重。
  • 每个历史 token 另有较窄的 indexer key。
  • indexer 对所有可见候选位置计算重要性分数，选 Top-k。
  • 主 Attention 在所选位置的 MLA latent 上计算真正的 Attention 权重并聚合。

简化索引打分：

I(t,j) = Σ_h w(t,h) · ReLU(q_index(t,h) · k_index(j))
S_t = TopK_j I(t,j)
o_t = MainAttention(Q_t, KV[S_t])

Indexer 的分数不是最终主 Attention 的 softmax 权重。 它只决定“读哪些位置”；主 Attention 还要在所选集合上独立打分与归一化。S3 式1–2

与 NSA 最重要的区别

NSA DSA / V3.2
选择依据 compression Attention 分数导出的块分数 独立学习的 lightning indexer
选择粒度 原始连续块 原始 token 位置
核心组合 摘要、选择、窗口三分支门控 所选 token 上的 sparse MLA
原论文/模型底座 GQA 实验架构 MLA
训练路径 原生可训练，论文从预训练验证 稠密模型继续训练：indexer warm-up 后适应稀疏

V3.2-Exp 官方参考实现中，indexer 默认 64 heads、head dim 128，Top-k=2048；主 KV latent rank=512，RoPE 维度=64。它仍然保留可见历史的主 KV cache 和 indexer key cache。选 2048，不等于只存 2048。S3 S6

索引器怎么学会选？

先冻结主模型、保留 dense Attention，用聚合后的主 Attention 分布通过 KL loss 训练 indexer；再引入稀疏选择，让主模型适应新的读取模式。稀疏阶段仍对所选集合对齐 indexer 分布。Top-k 不是自动可微的魔法，原论文为其设计了明确的学习路径。S3 §2.2

非常关键：索引器仍然要扫描历史

若有 n 个 Query、n 个候选，轻量 indexer 仍有 O(n²) 配对。主 Attention 降到约 O(nk)，不意味着整个模块已严格变成线性复杂度。原报告明确保留这个边界。S3 效率讨论

此外，参考演示代码为清楚表达语义，会先算稠密 score 再用 Top-k mask；不能拿这种 Python demo 的执行代价当成高效 sparse kernel 的实现。S6

06 / CSA：先压缩历史条目，再从摘要里选

Compressed Sparse Attention，压缩稀疏注意力。 与 MLA 的通道压缩不同，它首先把历史序列压成约 n/r 条表示，然后在压缩条目上做 DSA 风格的 Top-k。S4 §2.3.1

四步流程

  1. 学习式序列压缩：把连续 token 生成的 KV 候选按可学习权重合成为摘要。
  2. 压缩索引缓存：对 indexer key 也执行对应的序列压缩。
  3. 索引器扫描摘要：候选从 n 变成约 n/r，选择 k 条摘要。
  4. 核心 Attention：所选压缩条目与最近窗口中的未压缩条目一起参与核心 Attention。

不是简单平均池化，也不是压缩后再解压回原文

压缩器生成候选 C 和逐通道权重 logits Z，加入可学习位置偏置；对同一通道的窗口内位置做 softmax，再逐通道加权求和。可写成概念形式：

alpha[j,d] = softmax_over_positions(Z[j,d] + position_bias[j,d])
summary[d] = Σ_j alpha[j,d] · C[j,d]

V4 CSA 使用重叠结构：每步前进 r 个 token，一个摘要可涉及当前 r 个位置与前一段 r 个位置的不同投影，感受范围可达 2r；但输出摘要数仍约为 n/r，不是 n/(2r)。边界有单独处理。S4 式9–12S5

V4-Flash 快照实例

  • r=4：约每 4 个 token 产出一条压缩表示。
  • Top-k=512：选的是 512 条摘要，不是 512 个原始 token。
  • 局部窗口 w=128。
  • 核心共享 KV 宽度=512；这 512 已经包含最后 64 维 RoPE，不是“再加64变成576”。
  • 同一压缩条目用作核心 Attention 的 K 和 V，多 Query heads 共享；后续使用 grouped output projection。S4 S5

不能把“选512条摘要，r=4”直接当成“精确恢复2048个原始token”。重叠、非线性编码和有损聚合都改变了它的含义。NSA 的选择分支回读原始块，CSA 的主全局分支读摘要本身。

07 / HCA：更粗地压缩，然后把所有摘要都读一遍

Heavily Compressed Attention，强压缩注意力。 不是 Hierarchical Cross Attention，也不是一般意义的分层 Attention 的泛称。本文特指 DeepSeek-V4 报告的 HCA。S4 §2.3.2

  • 使用更大的 r′，该 V4 配置为 128。
  • 每 128 个位置形成一条摘要；这里不使用 CSA 的重叠压缩。
  • 没有 lightning indexer，也没有全局 Top-k 筛选。
  • 每个 Query 读取全部可见强压缩条目，并加入最近 128 个原始局部条目。

例如在长上下文中：

原始历史：131072 条
    ↓ 每128条学习式合成一条
强压缩历史：约1024条
    ↓ 不筛选，全部可见摘要都读
核心 Attention：约1024条全局摘要 + 128条局部条目

这里的“全局”是全部历史区域都有机会通过摘要影响输出，不等于保留并精确读取每个原始细节。

为什么 CSA 与 HCA 混合使用？

CSA 保留更细的全局摘要分辨率并选择相关位置；HCA 用更粗的分辨率保留广泛全局覆盖、免去索引器。它们是两种不同的压缩与读取权衡，而非仅仅不同 Top-k。S4

官方 V4-Flash 配置的 43 个主干层包含：前 2 层纯 SWA，随后 CSA/HCA 交替，共 21 个 CSA、20 个 HCA；配置列表第 44 项还包含一个 0，对应额外 next-token prediction 层而不是第44个主干层。这个排列是本次固定模型实例，不是所有 V4 变体的定律。S5

08 / 必须补回去的细节：因果、窗口、位置与缓存状态

为什么两种压缩层都要局部窗口？

压缩块尚未形成或当前 Query 所在块还未完整可见时，不能用“包含未来信息”的摘要。局部窗口补足近期依赖和当前块信息。实现维护局部环形缓存、未完成压缩的状态以及已完成摘要；不能仅按 n/r 的理想条目数计算整个 cache footprint。S4 §2.3.3, 系统实现S5

窗口不是永远与摘要互斥的时间范围。 某些近期历史可能既在窗口内，又已影响一个完整摘要；教学图把它们分开仅为看清信息来源。

三分支门控与“合并候选”不同

  • NSA：三次各自归一化的 Attention 输出，再经过学习门融合。
  • V4 CSA/HCA：压缩条目与窗口条目合并到核心 Attention 的候选集合；带可学习 attention sink。不要照搬 NSA 的三路门控图。S2 S4 S5

K=V 与 RoPE

V4 共享 KV MQA 对 Q 和共享 KV 的末尾64维使用 RoPE；因为这个共享向量也作 V，输出端对对应维度施加逆向的位置旋转，使贡献体现相对位置信息。这不是前面 Kimi NoPE 图的延续。S4 §2.3.3S5

算法、精度与实现必须分开

报告中的混合 KV 存储、indexer 低精度和专门 sparse kernel 都可能带来收益。FP8/FP4 不是 CSA/HCA 的定义本身；参考实现中也可能用 BF16 张量模拟量化数值。本文的条目数演示不把这些不同精度混成一个“显存倍数”。S4 S5 S6

09 / 数量与复杂度：主 Attention 少读，不代表所有部分都少做

统一符号：n 为序列长度，k 为所选条目上限，r/r′ 为压缩步长，b 为原始选择块长度，k_b 为所选块数，w 为窗口，s 为 NSA 摘要步长。忽略 head/width 常数、边界、Top-k 算法开销和投影成本，只比较相关性计算：

方法 单个晚期 Query 的核心读取项 额外定位工作 全序列主要配对数量级
dense MLA n 无 indexer O(n²)
NSA 约 n/s + k_b b + w 复用摘要分数，映射并选块 O(n²/s + n k_b b + nw)
DSA min(k,n) indexer 扫描 n 个候选 轻量 O(n²) + 核心 O(nk)
CSA min(k,n/r) + w indexer 扫描约 n/r 个摘要 轻量 O(n²/r) + 核心 O(nk+nw)
HCA 约 n/r′ + w 不做 indexer/Top-k O(n²/r′+nw)

“轻量”与“核心”的每次配对宽度、head 数和精度不同，不能把表中配对数直接相加当作 FLOPs。当 r′ 固定时，HCA 的全序列复杂度仍是带较小系数的二次项，并非数学上的线性 Attention。S1 S2 S3 S4 S5 S6 ，表为公式推导

用 n=131072 做一次可复算的教学估计

方法 定位候选量 核心读取预算 缓存容易误解的地方
MLA — 131072 个 token 位置 每位置宽度小，但位置数仍多
NSA 约8192个摘要，分数复用 约8192摘要 + 1024选中原始token + 512窗口 = 9728 分支条目 原始细粒度 KV 不能因本次未选中就永久丢弃
DSA 131072 个 indexer keys 2048 个 token 位置 主 cache 仍有131072个位置，另有索引缓存
CSA 32768 个压缩 indexer keys 512 摘要 + 128窗口 = 640 主历史是约32768个摘要，不是只保存512条
HCA — 1024 摘要 + 128窗口 = 1152 更强压缩、没有选择，但核心读项不一定比CSA少

此例把 n 视为可供估算的长历史，忽略前缀、未完成块与因果边界；不是某个 Query 的逐项精确 trace。不同类型“一个条目”的信息分辨率、宽度与精度不同；9728、2048、640、1152 不是速度排名。

10 / 应该如何理解“演进”的取舍？

关注点 需要问的问题
长上下文可装下 除主 KV 外，indexer cache、局部窗口、压缩器状态、并行复制占多少？
decode 延迟 indexer 扫描、Top-k、gather、核心 attention、输出投影，谁占主导？
prefill / 训练 完整 Query 集的相关性计算、反向传播与 compression 开销是多少？
精细检索质量 是读原始 token、细摘要还是粗摘要？遗漏与混合信息怎样被训练弥补？
GPU 实现 稀疏读取是否连续、是否复用、是否有真正稀疏 kernel？
比较公平性 是否相同模型规模、精度、batch、上下文长度、硬件和计时范围？

六个判断题

  1. “MLA 只存少量历史 token。” 错：通常是每个历史 token 存得窄。
  2. “DSA 选2048，所以 cache 只有2048条。” 错：选的是本次读取子集。
  3. “NSA 与 CSA 都压缩，所以选中后都读原始块。” 错：NSA selection 回读原始块；CSA 全局核心读选中摘要。
  4. “HCA 不稀疏，所以它又回到昂贵的原始 full attention。” 错：它全读的是强压缩后的摘要。
  5. “HCA 固定128倍压缩，所以整体复杂度是 O(n)。” 错：全序列仍有约 n²/128 配对项。
  6. “所有这些结构都是 dense Attention 的无损代数变形。” 错：只有给定 MLA 内部的合法吸收重排可保持等价；选择和序列聚合通常改变可见信息与模型函数。
