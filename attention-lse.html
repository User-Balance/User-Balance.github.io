01

LSE 是什么，位于 Attention 的哪一步？

LSE = Log-Sum-Exp，即“先取指数、求和，再取对数”。对固定的一个 query 和一个 head，把所有有效 key 的分数记为 sj：

sj = (q · kj) / √dk + biasj + maskj
Z = Σj∈有效 KV esj　　L = ln Z
pj = esj − L　　O = Σj pj vj

Attention 输出 O

输出 O 和 LSE 的职责不同

O 是对 V 的加权向量，送给后续投影。LSE 是每行的归一化统计；可以供分块归并和反向重算使用，通常不作为模型隐藏状态继续传播。

LSE 不是 loss，也不是注意力权重

它不是训练 loss，不是某个 key 的 pj，不是 entropy，也不是 max score。它只由 Q、K、scale、bias、mask 决定，不由 V 决定。

数学范围：标准 Softmax Attention，未加入 dropout 或额外 attention sink。稀疏 Attention 的“有效 KV”是选中的 key 集合。

02

为什么用 log，为什么还要减最大值？

直接计算 es 容易溢出。例如分数为 [1000, 999]，普通双精度直接取指数也会溢出；但 Softmax 仍有合法的结果。

m = maxj sj
L = m + ln Σj esj − m
pj = esj − m / Σk esk − m

稳定例子：s = [1000, 999]

m = 1000
Σ exp(s−m) = 1 + e⁻¹ ≈ 1.367879
L ≈ 1000.313262
p ≈ [0.731059, 0.268941]

所有分数共同平移 c

LSE(s+c) = LSE(s)+c
Softmax(s+c) = Softmax(s)

共同平移改变 LSE，却不改变输出 O。所以不能仅凭不同 query 的 LSE 大小判断“置信度”或“注意力更集中”。

使用 exp2，不等于接口返回 log2 LSE。有的 kernel 用 exp2 加速内部指数运算，最后把统计乘 ln2，仍返回自然对数。必须核对 backend 的输出约定。后面的源码示例同时展示这两种情况。

04

为什么 LSE 能让局部结果精确归并？

把同一个 query/head 的 key 集合切成互不重叠的块 Sr。每块独立计算自己的 Softmax：

Zr = Σj∈Sr esj
Lr = ln Zr　　Or = Σj∈Sr (esj/Zr) vj
全局 Z = Σr Zr
全局 O = Σr (Zr/Z) Or

局部 Or 已经除过 Zr，所以求和时要先恢复它对应的质量。通过 LSE，质量可以稳定地在 log 域恢复：

M = maxr Lr
ar = exp(Lr − M)
wr = ar / Σk ak
O = Σr wr Or
L = M + ln Σr ar
9∶1 例子：rank 0 的 Z₀=9、O₀=10；rank 1 的 Z₁=1、O₁=0。全局 O=(9×10+1×0)/10=9；简单平均得到 5，直接相加得到 10，二者都不正确。

两块合并也能继续合并

定义状态 (O,L)，先 merge(A,B)，再 merge(AB,C)。因为 key 集合的分母和未归一化分子都可相加，实数算术下结果与合并顺序无关。

因此支持逐块处理、树形归约、跨 CTA split-K 和跨 rank KV 分片。浮点加法顺序不同，结果允许有数值误差。

单个 LSE 不携带 V 的信息

只发送 LSE 无法恢复 Attention 输出。一般需要同时保留/交换局部 O 与 LSE，或先交换 LSE 再让每个 rank 校正自己的 O。

O 是向量；同一个 wr 用于该 query/head 的全部 V 分量。

def merge(partial_o, partial_lse):
    # 全部 partial 属于相同 query/head，KV 块互不重叠
    valid = [r for r in ranks if partial_lse[r] != -inf]
    if not valid:
        return zeros_like(partial_o[0]), -inf  # 显式边界约定
    m = max(partial_lse[r] for r in valid)
    a = [exp(partial_lse[r] - m) for r in valid]  # ln LSE
    denominator = sum(a)
    o = sum(a[r] * partial_o[valid[r]] for r in range(len(a))) / denominator
    lse = m + log(denominator)
    return o, lse

若接口给的是 L₂=log₂Z，把 exp/log 替换为 exp2/log2。转换关系：Le = L₂×ln2。不能对 log₂Z 直接套 exp。

FlashAttention 的 Online Softmax：同一数学，逐块更新

FlashAttention 不必把完整 Nq×Nk 分数/概率矩阵写回 HBM。处理一个 KV tile 后，维护每行的最大值 m、稳定分母 ℓ、稳定的未归一化输出 u：

m = max s　　ℓ = Σ es−m　　u = Σ es−mv
输出 O = u/ℓ　　LSE = m + ln ℓ

旧状态 (m,ℓ,u) 与新块 (mb,ℓb,ub) 的尺度可能不同，先统一到新最大值：

m′ = max(m,mb)
α = em−m′　　β = emb−m′
ℓ′ = αℓ + βℓb　　u′ = αu + βub
m、ℓ 与 LSE 不能互换。m 是行最大值，ℓ 是相对 m 缩放后的分母，LSE=m+lnℓ 才是完整归一化信息。只拿 m 做跨 rank 合并会丢掉“有多少指数质量”。

06

跨卡 DCP：每卡拥有一部分 KV，如何拿到全局 O？

下面展示逻辑阶段。对待归并的 query/head，各 KV owner 必须能得到所需的 Q；Q 可以通过复制、AllGather 或其他布局提供。每个 owner 只对自己持有的有效 KV 计算局部 O/LSE。

同一组 Q 可供所有 KV owners 使用
↓　局部计算彼此独立；每个 head 的 score 使用相同 scale / mask
↓　输出 Or 与归一化统计 Lr
↓　按 query/head 对齐来自不同 KV owners 的 partial

张量布局与统计开销



KV 切分轴和输出 head owner 是两回事。A2A 接收端为自己负责的 H/N 个 heads 收集来自 N 个 KV owners 的 partial。归并的是同一 head 在不同 KV 块上的输出，不是把不同 head 的结果做一次 Softmax。


A2A、AG→RS 与 Ring 是三种通信组织示意。实际后端可能选择不同布局；先保证同一 query/head 的 KV 集合、底数和 mask 契约一致。

哪些并行需要 LSE？先看切分的到底是哪一维


并行 / 分块拆开的对象LSE 如何使用


KV / Context Parallel同一 query/head 的 key 集合局部 O/LSE 加权合并；Ring 可在 Q owner 上按 KV 轮次累积状态。


DCPKV cache 分布在不同 rankOwner-local Attention 后，A2A 或 LSE AllGather＋O ReduceScatter。


Split-KV / Split-K同一 GPU 上不同 CTA 处理不同 key 区间相同归并数学；可能是单独 reduction kernel，也可能融合在后端内部。无需跨机器。


FlashAttention tiles一个 kernel 逐 tile 读取 KV在线 m/ℓ/u 更新，最后形成 LSE；不必每个 tile 都对外写出 LSE。


Prefix＋当前 chunk同一 query 的历史 KV 与当前段有效 KV两个不重叠的有效集合可用 O/LSE 合并；当前 chunk 仍需正确 causal mask。


按 head 的 TP不同 heads，各自看完整的有效 KV每个 head 自己计算 LSE；不同 heads 之间无需 LSE 合并。


Q/K feature 维 TP同一 score 的 dot-product 分量先求和得到完整 score，再做 Softmax。不能先对各 feature 分片做 Attention，再套 KV 的 LSE 归并。


只切 query 行的 SP / CP不同 queries，各自得到所需 KV各 query 的 LSE 独立，输出可按 query 行拼接；没有同一 query 跨 KV 的 partial 就无需此归并。


Attention DP / 普通 DP不同请求或不同模型副本每组内部计算；不能合并不同请求的 O/LSE。


PP / MoE EP不同层 / 不同专家LSE 可能仍由各层 Attention 产生，但不是 PP stage 或专家输出归并的权重。




判断规则：若拆开的计算是“同一个 query/head，看不同的不重叠 KV 集合”，就需要恢复统一的 Softmax 分母。若拆的是不同 query、不同 head、不同层或不同专家，不应直接套这个 LSE 归并。

稀疏 Indexer 与主 Attention 分开理解
Indexer 计算检索分数并选 TopK；主 Sparse MLA 在这些 selected keys 上做 Softmax。这里 LSE 归并恢复的是selected-key 并集上的 Attention，不会补回被 TopK 排除的 key。
KDA 不是这套 Softmax 归并

Prefix＋当前 chunk 也可以先得到各自的 O/LSE，再对同一 query 的不重叠有效 KV 集合归并。当前 chunk 的 causal mask、KV 写入与前缀依赖仍需满足；LSE 不能消除这些依赖。


Shape、通信打包与底数分支均是教学示例；T=384 仅用于复算，不代表任何服务的实时 batch。网页没有 GPU benchmark。





09
LSE 占多少显存？训练反向又为什么保存它？


前向临时统计，通常是 FP32
LSE：T × H × 4 bytes
O：T × H × d_v × bytes_per_element
当 d_v=512 且 O 为 BF16，LSE 与 O 的字节比为 4/(512×2)=0.390625%。LSE 很小，但 O 通信、发送/接收缓冲、layout staging 仍可能较大。
T=384、H=96 的 DCP8 示例
partial LSE ≈ 144 KiB / rank
partial O ≈ 36 MiB / rank
packed payload ≈ 36.140625 MiB / rank
这是单个逻辑 payload 的尺寸。双缓冲、Graph 预分配或 staging 会另加，不能当作整个通信峰值。


LSE 与 KV cache 的容量轴不同：LSE 对应本次处理的 query 行和 heads；KV cache 对应持久保存的 key tokens 与层数。Decode 时 query 行通常接近本次请求数，不必等于历史上下文长度。LSE 也不是模型权重，不因保存一份 checkpoint 就永久驻留。


容量预算时：LSE 属于前向临时统计/归并缓冲，不能把它按“全部历史 token×全部 heads×全部层”无条件计入持久 KV。实际内存生命周期由后端、训练/推理模式、Graph 和缓冲复用决定。


反向传播：用 LSE 重构概率，避免保存完整 P
训练反向需要 Softmax 的概率 P。保存每 query/head 的 LSE 后，可以重新计算 tile 的 score，再恢复 P = exp(S−LSE)，而无需把完整 Attention 概率矩阵长期存进 HBM。


dP = dO Vᵀ
Di = Σj PijdPij = dOi · Oi
dSij = Pij(dPij − Di)


上述反向公式为标准无 dropout、scale 已体现在 S 的例子。实际还需 Q/K/V、scale、mask/bias 以及必要的随机状态；只保存 LSE 无法独自完成反向。推理一般不需要保留反向所需统计，但分块或 DCP 归并仍会使用 LSE。





10
边界条件与容易混淆的地方


一个 rank 没有有效 KV，该返回什么？
该分片 Z_r=0，按数学约定 L_r=−∞，局部 O_r 使用零向量占位。归并中它的质量为 0，不影响非空分片。避免出现 0×NaN，空分片输出应在进入 combine 前规范化。


如果所有 rank 都没有有效 KV？
全局分母为 0，普通 Softmax 输出没有定义。系统需要显式约定或避免此输入。页面显示 O=0、LSE=−∞并标记边界；归并一般包含 acc/weight_sum；所有分片全空时必须有显式保护，不能把页面约定当作已验证的后端行为。


合并 LSE 是直接相加、取最大值吗？
都不是。全局 LSE = logsumexp(局部 LSE)。局部 LSE 直接相加对应分母相乘，取最大值会丢掉其他分片的质量；只有其他质量可忽略时才近似最大值。


相同分数能按 rank 平均吗？
只有各 rank 的总指数质量 Z_r 相同时，简单平均才恰好正确。所有 key 分数相同但各 rank 有效 token 数不同，Z_r 与 token 数成正比，仍需按数量对应的质量加权。


有重叠 KV、attention sink、padding 或重复 TopK 怎么办？
上述归并要求有效 KV 块形成无重复的集合划分。重叠或重复 key 会重复计分母；sink 若在每块复制也可能被重复计入。Padding、无效索引和 future token 要按 query 的 mask 排除。稀疏 backend 是否去重以及 sink 规则须单独核对。


LSE 能消除通信、因果依赖或增加 KV 容量吗？
不能。LSE 提供可组合的归一化统计；各 rank 仍需要所需的 Q、本地 KV 和局部输出，通信与同步也仍存在。Chunk B 读 Chunk A 的 KV 前，A 的 KV 写入必须完成。


exp2 比 exp 快，所以我能直接换底数吗？
不能只换函数。自然对数 LSE 配 exp；log2 LSE 配 exp2。若内部实现 exp(s)=exp2(s×log2(e))，输入也必须转换尺度。页面的错误底数卡片展示了错配后的数值变化。


防御性实现把 NaN / +∞ LSE 处理成 −∞，可以认为它们都是空 KV 吗？
数学上不能。−∞ 可表示零质量；NaN/+∞可能来自溢出、错误索引、错误 backend 契约或其他上游问题。某些 kernel 做防御性替换，不应据此把异常输入当作合法空分片，调试时仍须检查来源。


自测：两个 rank 输出相同，还需要 LSE 吗？
如果 O₀=O₁，则任意合法质量加权都得到同一个 O。观察到输出相同不足以证明简单平均的实现正确，因为换一组 V 就可能暴露误差。
两个分片都只保存 O=10，但一个分片 Z=1、另一个 Z=100。只看 O 无法推断质量比例。如果第三个分片 O=0、Z=9，是否正确保存了 LSE 就会改变合并结果。
