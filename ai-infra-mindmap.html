AI Infra / 总览

AI Infra 是什么？

它是连接“模型算法”和“可用产品”的系统工程：让同一个模型能在集群上稳定训练、在反馈中对齐、被客观测评，并以可接受的延迟和成本服务用户。

解决什么问题

把模型代码、数据、算力和服务流程组织成可复用、可观测、可恢复的系统。

核心关注点

性能（吞吐/延迟）、成本（算力/显存）、质量（精度/安全）、可靠性（故障/回滚）。

如何理解
把 AI Infra 想成“模型工厂”：框架负责画生产流程，算子是工位，runtime 是调度员，硬件是厂房与机器，测评是质检，推理服务是交付渠道。

可以把一次 y = softmax(QKᵀ / √d)V 的执行想成一条生产线：上层描述意图，中层拆成算子，底层安排内存、通信和 kernel。

模型 / 应用Transformer、RAG、Agent、训练脚本描述“要解决什么任务”，包含网络结构、数据流和业务约束。
框架PyTorch、JAX、TensorFlow、Megatron-LM、DeepSpeed、FSDP提供张量、自动微分、计算图、分布式并行和 checkpoint 等抽象。
编译 / 图层TorchDynamo / FX、AOTAutograd、XLA、MLIR、ONNX捕获计算图、做 shape/布局/融合优化，把动态图变成更适合执行的计划。
算子 / KernelGEMM、FlashAttention、RMSNorm、RoPE、AllReduce、Triton、CUTLASS对具体张量形状、数据类型和设备执行一小段计算；性能常由 kernel 决定。
RuntimeCUDA Runtime、NCCL、CUDA Graph、vLLM、TensorRT-LLM、SGLang管理 stream、event、内存、通信、请求调度、KV cache 和执行顺序。
硬件 / 系统GPU/TPU/NPU、HBM、NVLink、InfiniBand、K8s、Slurm真正提供 FLOPs、显存带宽、节点间带宽，以及资源隔离和故障恢复能力。

第四张图：一组高频词的“人话”解释

先把这些词放进正确的层级，再去看论文、代码或系统 benchmark，会更容易判断瓶颈在哪里。

FLOPs / FLOPS运算量 / 每秒浮点运算能力；是“理论速度”，不等于真实吞吐。
MFU / HFU模型/硬件 FLOPs 利用率；看理论峰值有多少真正变成了有效计算。
DP / TP / PP / EP数据、张量、流水线、专家并行；分别切 batch、权重张量、层、MoE experts。
AllReduce / AllGather / All-to-All集体通信原语；训练同步梯度，MoE 路由 token，常见瓶颈是网络。
Prefill / DecodePrefill 一次处理输入上下文，Decode 逐 token 生成；两者算力和调度特征不同。
KV Cache缓存已经算过的 Key/Value，后续生成只追加新 token，减少重复计算和延迟。
TTFT / TPOT / ITL首 token 时间、每输出 token 时间、token 间隔；分别描述“等多久”和“生成多快”。
Continuous Batching请求完成就补入新请求，动态拼 batch；比固定 batch 更适合在线生成。
PTQ / QAT训练后量化 / 量化感知训练；前者快，后者更能补偿精度损失。
W8A8 / W4A16 / FP8权重/激活的 bit 组合；位宽越低通常越省显存，但越依赖硬件和校准。
Speculative Decoding小 draft 模型先猜多个 token，大模型批量验证；接受率、草稿成本和验证开销共同决定收益。
PPO / GRPO / DPOPPO/GRPO 是策略优化方法；DPO 是直接偏好优化，通常无需在线 rollout。
Actor / Critic / Reward Model行动策略、价值估计、奖励打分；是 RL 训练闭环的三个常见角色。
pass@k / Win Rate / ECE代码通过率、偏好胜率、校准误差；分别看能力、偏好和置信度。
p50 / p95 / p99延迟分位数；p99 常比平均值更能暴露线上长尾。
Checkpoint / Fault Tolerance保存训练状态并可恢复；大规模训练要把故障当成常态设计。
Kernel Fusion把多个小算子合并成一个 kernel，减少读写显存和 launch 开销。
Roofline / Memory-bound用算力与带宽判断瓶颈；很多 Decode 阶段更像“搬数据”而非“算不动”。

第五张图：建议的学习顺序

先建立“数据流和张量形状”的直觉，再深入并行、kernel、runtime 和服务指标。

先看模型计算掌握 Transformer 的 Q/K/V、GEMM、Attention、Norm，以及 [B,T,d] 的 shape。
再看训练并行理解 DP/TP/PP/EP、AllReduce、显存组成、checkpoint 和 MFU。
再看推理链路区分 Prefill/Decode，理解 KV Cache、continuous batching、TTFT/TPOT。
再看算子与 runtime用 profiler 找 kernel、显存带宽、通信、launch 和调度瓶颈。
最后看优化比较 Flash/PagedAttention、量化、kernel fusion、投机推理的收益与代价。
用测评闭环同时看质量、安全、吞吐、延迟、成本和回归，避免只优化单一指标。
这张脑图的主线：把“模型能算”推进到“系统能稳定、便宜、快速、可信地运行”。
