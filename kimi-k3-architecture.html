1. 符号与形状约定

  • B：序列数；S：当前输入序列长度；T：当前步 packed token 总数。等长完整输入可用 T=B×S。
  • L：已缓存的上下文长度，不能与本次输入长度混用。普通逐 token decode 时 T=B；speculative verify 不一定如此。
  • D=7168：文本隐藏维度；H=96：Attention 总头数。
  • 主表使用全模型逻辑形状，不含 TP/EP 切分、padding、量化打包或 kernel 私有布局。
  • 表中线性权重统一写成 [输入维度, 输出维度]，对应 Y=XW；PyTorch nn.Linear.weight 的存储通常是反过来的 [out, in]。
  • 下文的模块是数学/模型结构，不代表每个框都单独启动一个 GPU kernel。

2. 整模型与 93 层排列

层号使用 1-based：

第  5～ 8 层：KDA   KDA   KDA   MLA

第 89～92 层：KDA   KDA   KDA   MLA

3. 单层：不能只画普通 residual add

AttnRes 的候选来自模型深度方向的块摘要，不是历史 token 的 KV。逻辑操作：

  1. 收集历史块摘要和当前块 partial，形状可写作 [T,K+1,7168]。
  2. 对每个候选做 RMS 归一化，使用可学习投影得到标量分数 [T,K+1]。
  3. 沿块轴 softmax，使用这些权重对原始候选向量加权求和，输出 [T,7168]。
  4. Attention 和 FFN 各有自己的 AttnRes 参数，最终模型输出也有一次 AttnRes。
  5. attn_res_block_size=12；参考实现于 0-based 层号 0,12,24,…,84 的边界存入前一段 partial 并开启新块。首个存入的候选包含输入 embedding，因此不能简单理解为“只保存每 12 层的单层输出”。

这里的第 10 步概率矩阵是数学形状，融合 attention kernel 通常不把它整体写到显存。Q 的 64 维分支也是每头独立；只有 K 的 64 维分支是跨头共享。

与用户图同样取 B=1,S=2048 时：

  • 输入：[1,2048,7168]。
  • Q、K：[1,96,2048,192]，不是 [1,128,2048,192]。
  • V、Attention 输出：[1,96,2048,128]。
  • Flatten：[1,2048,12288]。
  • 门控和 o_proj 后：[1,2048,7168]。

4.3 MLA decode 的吸收形式与压缩 KV

上图是便于理解的显式展开语义。高效 MLA 后端可以把 K/V 升维矩阵吸收到两侧，避免缓存历史 token 的展开 K/V：

对第 i 个 head，使用行向量约定：

K_content,j = c_j W_K,i        W_K,i: [512,128]
V_j         = c_j W_V,i        W_V,i: [512,128]

q̂_i        = q_content,i W_K,iᵀ       → [512]
score(i,j)  = (q̂_i c_jᵀ + q_shared,i k_shared,jᵀ) / √192
z_i         = Σ_j softmax(score(i,j)) c_j            → [512]
out_i       = z_i W_V,i                             → [128]

**后端边界：**参考 Transformers 实现的 past_key_values.update 接收展开 K/V；SGLang MLA 优化路径使用压缩 latent 缓存。不能把“模型支持 MLA 压缩”写成“任何实现都一定只存 576 维”。

5. KDA：69 层线性递推 Attention

KDA 不是把 MLA 的头数改一下；它不用一份无限增长的历史 K/V 列表来完成每一步注意力。

路径 权重 [in,out] 输出逻辑形状 作用
Q 投影 [7168,12288] [T,96,128] 读取状态的 query
K 投影 [7168,12288] [T,96,128] 更新状态的 key
V 投影 [7168,12288] [T,96,128] 写入内容
三组 short conv 每通道 kernel 4 各 [T,12288] 局部时序信息，激活是 SiLU
f_a_proj [7168,128] [T,128] 遗忘门低秩中间表示
f_b_proj [128,12288] [T,96,128] 每头、每通道遗忘门参数
b_proj [7168,96] [T,96] beta 更新强度
KDA core 无普通 dense 投影权重 [T,96,128] 结合递推状态、Q/K/V 和门
output gated RMSNorm norm [128] [T,96,128] RMSNorm 后乘 sigmoid 输出门
g_proj [7168,12288] [T,96,128] 全秩输出门
o_proj [12288,7168] [T,7168] 回到主干宽度
  • 该配置 use_full_rank_gate=true：输出门 G 是全秩投影；不要与低秩的 f_a/f_b 遗忘门混淆。
  • gate_lower_bound=-5.0 是遗忘门相关 kernel 参数，不等于把最终输出乘以 -5，也不能直接解释为固定衰减率。
  • Prefill 可用 chunk KDA，decode 可用 recurrent KDA；实现会融合 Q/K 归一化、门函数和 beta sigmoid。选择受模式/后端约束，不保证每次请求都调用同一个 kernel。
  • 概念递推状态每层为 [B,96,128,128]；最后两个维度的实际转置、分片和步长取决于后端。
  • 短卷积另需状态；所读 SGLang 实现采用 K−1=3 步历史缓存，Q/K/V 合并后 TP1 的每 slot 形状为 [3,36864]。其他实现可能分开存或保留不同长度的环形缓冲。
  • KDA 状态容量不随完整上下文 L 线性增长，但随活跃序列数、层数、头数增长；不是“没有缓存”，也不是“prefill 总耗时与长度无关”。

6. Stable LatentMoE：路由、专家与共享分支分开看

阶段 权重 [in,out] / 数量 输出 关键点
Router [7168,896] [T,896] 读原始 7168 维输入，不是 3584 latent
Top-16 无线性权重 ID、权重各 [T,16] sigmoid score 加 correction bias 用于选择
路由权重 无线性权重 [T,16] 被选专家的原 sigmoid score 再归一化；不是把 correction bias 加进权重
Latent down [7168,3584] [T,3584] 所有 routed experts 共享这次降维
Expert gate/up 每专家两个 [3584,3072] 两路 [M_e,3072] 可融合为 [3584,6144] GEMM
Expert activation SiTU-GLU [M_e,3072] 不是标准 SwiGLU
Expert down 每专家 [3072,3584] [M_e,3584] 专家在 latent 空间计算
Combine Top16 权重 [T,3584] 按原 token 归并
Latent RMSNorm [3584] [T,3584] 在专家结果聚合后、升维前
Latent up [3584,7168] [T,7168] 回到主干 hidden
Shared gate/up 两路各 [7168,6144] 两路 [T,6144] 始终计算，不参加 Top16
Shared down [6144,7168] [T,7168] 与 routed 结果相加

M_e 是发给专家 e 的 token 数，不一定等于 T，也不是负载均衡的固定值。分布式运行时可使用 All-to-All 做 dispatch/combine，但这是执行映射，不是模型新增层。

该快照的 SiTU-GLU，令 gate/up 两路为 g、u：

SiTU-GLU(g,u) = [4·tanh(g/4)·sigmoid(g)] × [25·tanh(u/25)]

第 1 层 Dense FFN：7168 → (33792 gate, 33792 up) → SiTU-GLU → 33792 → 7168，融合 gate/up 输出宽度为 67584。

7. 缓存与精度：哪些是真正随上下文增长的

数据 全模型单层逻辑形状 是否随 L 增长 说明
MLA 压缩 KV 每序列 [L,576] 是 512 个归一化 latent + 64 个 shared K；须后端支持
MLA 显式 KV K [L,96,192]；V [L,96,128] 是 参考实现/展开语义，不应假定始终使用压缩缓存
KDA recurrent state [B,96,128,128] 否 与活跃序列数 B 相关
KDA short-conv state Q/K/V 各若干历史步 × 12288 通道 否 固定窗口，具体物理布局取决于后端
AttnRes bank [T,K,7168] 不是历史 token KV 当前 forward 的深度聚合工作区，K 为历史块数

若采用 BF16 压缩 MLA cache，忽略 allocator、页表、padding 和元数据：

  • 每 token、每 MLA 层：576 × 2 = 1152 bytes = 1.125 KiB。
  • 24 个 MLA 层合计：每上下文 token 27 KiB。
  • 单序列上下文 L=2048：仅这部分为 54 MiB。
  • 这不是整模型显存：不含权重、KDA 状态、激活、AttnRes 工作区、并行复制与通信缓冲。

相同元素精度下，相比按 96 头显式存 K192+V128 的逻辑基线，维度比为 96×(192+128)/576 ≈ 53.33；这是缓存元素数比较，不是整个服务显存或速度提升倍数。

配置中的主 dtype 是 BF16，而 routed experts 使用 MXFP4 权重量化配置。不能据此说所有模块/激活/KV 都是 FP4：配置显式排除了 self-attention、shared experts、普通 dense MLP、LM head、vision 与 projector 等；运行时激活精度和缓存精度仍受后端设置约束。

9. 原生视觉入口的边界

此配置不是纯文本模型外壳。视觉配置给出了：patch size 14、视觉 hidden 1024、27 层、12 heads、QKV total width 1536、MLP intermediate 4096、空间 merge 2×2、投影到文本 hidden 7168。

但原始图像/视频 → 裁剪/分辨率 → patch 数 → 合并后视觉 token 数，依赖预处理和媒体布局。本报告不凭 hidden size 推测固定输入分辨率，也不把视觉头维度简单写成 1024/12。
